# Behavior Graph Slimming Engine 2.5.0

## Scope and invariants

This module was developed from BehaviorNodeIdLimitFix and the pinned CommonLibSSE-NG Havok declarations. Development used the supplied Skyrim reference binaries for independent verification. The branch starts from the verified 1.0.7 workspace. Its benchmark uses the trace, plan and instance cache headers saved from that same workspace before the optimizer changes.

An instance still owns its Skyrim/Havok graph. Runtime clips have playback, trigger and binding fields. State machines own transition state and links. Bindable objects also have runtime caches. Native cloning and cleanup carry and recycle node IDs. Equal serialized configuration alone establishes neither interchangeability nor ownership. This build reports zero native objects removed and performs no Havok object interning. It uses processing optimizations for these types.

## Processing

1. The existing InitNodeIds and PreSetup call hooks keep their original chaining and order. There are zero new hooks or relocations. The known native initialization path invalidates cached instances for the graph and any graphs sharing its transition data. After a successful native call it also checks for replacement transition data.
2. The first encounter traverses the live graph in discovery order. Verified static leaf routines can be skipped on 1.7.104.0. The empty-node signature folds four zero bytes into one multiplication and produces the same FNV value and disk key as the original loop.
3. The disk plan stays pointer-free and versioned. Runtime, name and structural/classification fingerprints select a variant. Actual state-machine ordinals are checked against the live graph. Edits that change the plan's inputs naturally select a new variant. Changes to playback data with the same graph structure and state-machine ordinals can safely reuse the plan because playback fields are never replaced.
4. Graphs with outstanding live IDs skip traversal, and the live-ID guard is repeated at commit. A revision check rejects prepared work from before the graph's observed native reinitialization, including when addresses are reused. On 1.5.97.0, 1.6.1170.0 and 1.7.104.0 a table can be reused when all keys, values, counts and probe positions match the live plan. With map reuse enabled, the commit checks the map before scanning all current IDs. If the map already needs replacement, it skips that extra ID scan. When replacement is needed, the verified native insert entry is checked live. The replacement table passes the same full content check before its data or the IDs are published. The 32,766 State Machine limit follows the signed engine fields. The commit validates sorted state-machine ordinals, dense assignments, the map header and the complete writable bucket span. Before staging, the runtime checks the complete native insert function against the qualified reference fingerprint. Staged insertion checks buffer identity, capacity and count at each step and validates the completed table before publishing it. Compaction that needs to rebuild a table requires a verified allocator and map layout.
5. After validation and ID commit, the optional optimizer stores a replay record. Empty child lists take a dedicated capture path. Nonempty lists use 16-bit ordinal encoding up to 65,535 nodes and 24-bit encoding for larger supported graphs. Null edges use a width-specific sentinel. Packing selects the ordinal width once and publishes only a complete replacement. Moving a capture transfers its validity and clears the source. Portable records reject redundant empty rows, which the writer omits. Both readers and writers check reachability, ordinal order and the plan fingerprint. Validation walks the nonempty rows and folds consecutive empty nodes into the same FNV stream in groups. It retains the raw form on allocation failure. Capture recalculates its capacity budget when storage grows and releases its buffers if the budget is exceeded.
6. Exactly equal plugin-owned topology and ID-plan data can share one immutable payload. A weak index keeps two candidates in each of 32 buckets, so two alternating graphs with the same bucket can share their existing payloads. A full bucket replaces its oldest candidate and prefers reusing an expired entry when available. Exact row, edge and state-machine comparisons authorize sharing. A publication recheck coalesces matching concurrent captures and skips candidates already compared. Comparisons run outside the bucket lock. The eight-entry instance cache charges each shared payload once against the 64 MiB total and includes it in the 32 MiB per-entry limit. Invalidation and admission detach old snapshots while holding the commit lock and release their buffers after unlocking. Live node pointers are held separately per instance and remain in RAM.
7. Replay, portable validation and comparisons between different encodings select their ordinal reader before traversing the edges. On replay, a live root and previously matched parent edges establish each ordinal before dereference. A changed edge, classification, identity or init generation returns to full analysis. State maps and ID bookkeeping are still verified before applying a plan. A saved plan needs no second disk lookup on a fast hit. Write failures remain retryable.

Skyrim owns the live Havok objects. An analysis reserves its graph and transition data for its lifetime. Native initialization invalidates the reservation and remains governed by the engine. Traversal and replay recheck invalidation after the maximum-child query, before requesting the child array and before consuming its pointers. When Havok returns a replacement child array, the plugin checks its writable address range and excludes overlap with the supplied scratch buffer before reading it or passing it to the native free routine. Publication checks the graph again under the commit lock. These checks rely on Skyrim's native lifetime rules within a running callback.

Topology-file locks are striped by graph variant. The file locks can precede the cache memory lock, and the commit lock can precede the cache memory or instance lock. Cache operations release their memory lock before beginning file I/O. Engine traversal runs outside file and commit locks. Each thread may retain up to 1 MiB of reusable traversal storage. Buffers are retained separately, so an oversized graph or nested traversal can leave smaller child, index and topology buffers available for the next graph. A failed prepared-plan check reuses the already validated prefix of the classification. Future disk-traversal shortcuts require an authoritative signature for the effective graph source, including loose-file and archive overrides, or a matching native lifetime guarantee.

## Configuration

SKSE reads `Data/SKSE/Plugins/BehaviorNodeIdLimitFix.ini` at game launch. Settings are independent of the ID fix.

| Setting | Effect |
| --- | --- |
| `bEnableNodeOptimization` | Master switch for the new hashing shortcut, packing, exact table reuse and content deduplication. |
| `bEnableSafeDeduplication` | Controls content-based sharing of exact immutable graph payloads across instances. |
| `bEnableGraphOptimization` | Controls ordinal packing, empty-node hash folding and exact table reuse. |
| `bEnableInstanceFastPath` | Controls RAM instance capture and replay. |
| `bEnablePersistentOptimizationCache` | Controls the disk-backed plan cache and its associated RAM lookup. |
| `bEnableExperimentalOptimizations` | Defaults to false. There are zero qualified experimental rules in this build. |
| `bEnablePerformanceLogging` | Enables per-hook timing summaries and large-graph details in `BehaviorNodeIdLimitFix.log`. |
| `bEnableAdaptivePreloading` | Enables startup preparation of enabled cache sources. |
| `bPrecomputeOfflineGraphs` | Builds replay candidates from supported standalone loose behavior HKX on verified Skyrim runtimes. Requires the persistent cache. |
| `bShowPreloadProgress` | Shows an interactive startup window and waits before the main menu. With the window disabled, startup does not block. |
| `bPreloadAnimationFiles` | Defaults to false. When enabled, warms loose behavior and animation HKX files deployed in Data. |
| `iPreloadMaxPlans` | Targets up to 128 valid startup plan candidates by default. Accepted range is 1 to 256. |
| `iPreloadAssetMaxMiB` | Caps buffered HKX reads at 4,096 MiB by default, subject to available RAM. Accepted range is 64 to 8,192 MiB. |

The log reports graph nodes, state machines, native removals, shared plugin payloads, measured payload capacity before and after prepare, map bucket bytes before and after commit, and actual changed IDs. Capacity metrics describe tracked storage and exclude allocator overhead and process RSS. A shared record adds no new topology payload capacity but still has its own list of live pointers. The timing summaries track the native call and plugin work separately.

### Performance log

Each graph hook contributes a result and durations for native and plugin work. Per-hook histograms report a bucketed P95 upper bound. Large-graph logs report commit work and lock wait separately, and the startup timers stop at the end of their own phases. The summary reports speculative offline replay and exact offline reuse separately. The worker writes and flushes a summary every three seconds when there has been activity. It includes graphs below the ID threshold and guarded skips alongside the individual cache and compaction paths. The first report explicitly indicates if no graph hook has arrived. Detailed rows for large graphs include traversal, planning, cache and commit timings. The hook queues up to 64 detail rows for the background reporter, which writes them with their original timestamps. The log counts drops at capacity or lock contention. Summary counters remain independent of those drops. The P95 upper estimate uses the measured maximum when it is tighter than the bucket boundary.

## Adaptive preloading

After SKSE loads its plugins, a low-priority worker checks existing plan files and prepares dense node ID tables before the main menu. It favors a recent variant per graph key, then uses remaining slots to warm older variants. Unusable records can be replaced by later candidates with at most 32 additional file candidates checked. The progress total adjusts only when more checks are needed, and the log reports the unusable count. It admits up to 16 MiB of serialized plans and 32 MiB of prepared IDs, with a 4 MiB limit per ID table. Valid larger plans can still warm the ordinary cache. The warmed entries share the cache with ordinary live entries. Accessing a prepared plan refreshes its eviction priority, and plan admission counts actual serialized plan bytes for combined files.

With `bPreloadAnimationFiles` enabled, the worker also reads effective loose HKX files into the Windows file cache. It prioritizes behavior and character graphs, including loose first-person project files and skeletons. A bounded first group reserves room for loose Open Animation Replacer files found in either documented directory layout. The remaining animation scan skips OAR subtrees already covered by the priority pass. A partial priority scan leaves the subtree eligible for the regular scan and filters any files already selected. Each group gets a bounded discovery pass. The file budget is limited to one quarter of available RAM, with at least 2 GiB of headroom, and the configured maximum. File I/O runs at background priority. Windows can reclaim these cached pages when needed. Assets in BSA archives use Skyrim's ordinary loading.

The progress window shows the checked count for each batch. The main menu waits for completed cache preparation or cancellation. Use Cancel, Escape or the close button. Startup has no elapsed-time limit. The plan, RAM and candidate limits still apply. Cancellation releases Skyrim immediately and requests cancellation of pending file I/O. If the progress window fails to start, the worker can continue in the background until the main menu. An explicit cancel or close still ends the wait. Cache publication releases the menu before diagnostic writes. The waiting callback, window and worker keep the startup signals alive only while they need them. The log reports candidates, counts, bytes and elapsed time.

At a graph's first use, a prepared candidate is checked during the live traversal. The hook matches every state-machine position, the total node count and the topology fingerprint. On a match, it uses the prepared IDs and skips the separate classification pass, disk lookup and assignment-plan build. The log marks this path as `traversal=preload-fast`. After live traversal observes a different shape under the same name, later instances use the exact shape lookup. The previous preparation remains available even when the newly observed shape has no prepared plan yet. A failed verification for the prepared shape can retire the disk candidate for the session. When a complete live traversal confirms the ID plan after a failed disk topology replay, the cache retains the same dense ID table without copying it. It drops the replay payload and allows the live capture to replace the stored topology. New and changed graph variants take the normal path and update the persistent cache when first encountered. The graph identity and native map guards still run at commit.

### Offline HKX analysis

The startup worker reads the data and fixup tables of supported 64-bit Havok 2010.2 packfiles from loose actor behavior directories on NTFS. It walks reachable local state machines, clip generators, manual selectors and modifier generators with no modifier. It derives discovery order and state-machine ordinals without creating any Havok objects. Files with external behavior references, transition effects or unrecognized reachable types use the standard runtime path. The worker scans character behaviors first, including first-person behaviors. Its catalog retains at most 32 candidates during enumeration and prefers the character candidates before sorting the final list. A preliminary check reads only the packfile header when it can rule out a plan, including invalid root and root-class offsets. The parser verifies the root virtual object before allocating pointer fixups. It collects generators and checks transitions in one pass per state machine. Empty nodes use the existing compatible signature fold, and large padding and edge lists are checked periodically for cancellation. The offline log reports the amount of source data read.

The plugin stores offline results in portable source-stamped records under `Cache/Offline`. A replacement or in-place edit invalidates the stored result even when the file size is unchanged. The file stamp is rechecked on the opened source after a cache hit as well as after analysis. A stamp change during that work discards the result for the current pass. A cached unsupported result avoids rescanning the same source. Offline records stay outside the ordinary ID-plan cache. The game validates every edge, alias and state-machine position using the live replay path before any offline plan is eligible for the existing commit. An accepted replay appears as `traversal=offline-topology`. Multiple variants and a failed speculative candidate use a later lookup by the observed shape. That path requires exact live links and state-machine ordinals and appears as `traversal=offline-verified`. Once the links match, the verified payload can be reused without comparing the same links again. A temporary replay allocation failure preserves the candidate. Resident offline preparations may use up to 24 MiB and 16 plans. The cache checks the minimum cost, duplicates and existing live topology before allocating dense IDs. It rechecks admission under the memory lock before publishing the plan and accounts for the actual retained capacity. The progress window and startup log report the offline phase separately.

### Persistent graph topology

On a successful first initialization of an eligible large graph, the plugin captures the ordered links and compact assignment plan. A bounded background job writes both in a versioned .graph cache record, keyed by runtime graph and variant. The instance path retries deferred or failed writes on subsequent use. At most four write jobs can be reserved at once, and callers can still confirm an already committed topology while all slots are occupied. A successfully written combined graph also satisfies persistence for its embedded plan. Topology validation must pass before the writer can replace a file or mark the write as saved. A later valid capture can still publish after the normal retry delay. The separate plan is eligible for retry if that topology is later rejected and there was a failed companion write. Disk failures have a 30-second retry delay. Stale jobs cannot cancel newer requests, and an active topology job keeps its plan record until the write finishes. Startup verifies the graph key and the embedded ID plan before reading the topology. Combined records can be preloaded and supply their plans independently, including a complete plan whose optional topology is missing. Startup reuses the shape fingerprint checked while decoding the combined record. The standard plan cache still provides a fallback. A direct load checks the plan variant before admitting it into memory. If the separate plan does not match, a valid combined record can still supply the right plan. A missing or invalid current plan also permits a matching legacy entry after the combined lookup. The live graph still authorizes migration. Small plan files use one bounded stack read. Large arrays and embedded offline plans read their ordinals directly into the final vector after the header and declared length agree. On supported filesystems an atomic replacement publishes a new file while readers holding the previous file finish reading its contents. Preloading can attach a prepared plan to a matching committed in-memory record. Existing .topo records are validated and converted automatically. The live path checks links, unique node identity and state-machine positions. A confirmed match appears as `traversal=disk-topology`. Skyrim creates and owns the native Havok objects.

New or changed graphs take the regular route and learn their own topology. A missing, invalid or oversized record leaves the ordinary plan path available. Topology payloads use up to 2 MiB per file and 24 MiB of startup topology storage. First capture happens on native graph initialization so the saved order includes the graph as Skyrim and active mods actually assembled it.

### Persistent HKX index

`Data/SKSE/Plugins/BehaviorNodeIdLimitFix/Cache/HKXIndex.bin` stores relative names and complete directory listings. On NTFS, the worker checks directory identity and change timestamps and enumerates the folders that changed. Updated listings are written by atomic replacement. When the index reaches its byte, item or folder budget, the writer retains verified listings in discovery order and carries over older listings that still fit. It skips atomic replacement if the selected index is identical to the one already saved. Incomplete scans, including a depth-limited traversal, preserve unvisited index entries that fit. Corrupt indexes, MO2 virtual paths and directories without reliable metadata use normal enumeration.

Loading and checksumming the index honors cancellation and the caller deadline in bounded chunks. The index persists across Windows restarts. Opening a selected HKX checks the current file and its size, including edits in place that preserve the directory listing. The startup log reports `indexHits`, `directoriesScanned`, `indexSaved` and `indexLimited`. Windows caches the file bytes in RAM.

## Source review and compatibility

The source review reran the read-only EXE and Address Library checks for Skyrim 1.5.97.0, 1.6.1170.0 and 1.7.104.0. These checks include both hook sites, the Havok child rules, map allocator slots and the complete native insert body and the instruction that preserves the staged borrowed flag. The matching SKSE references are 2.0.20, 2.2.8 and 2.3.1, respectively.

| Skyrim | Address Library ID | Native insert RVA range (end exclusive) | Executable evidence |
| --- | --- | --- | --- |
| 1.5.97.0 | 56771 | `0x9CAAD0–0x9CAB79` | Hash-verified unpacked analysis copy |
| 1.6.1170.0 | 57198 | `0xA8C690–0xA8C739` | Hash-verified unpacked analysis copy |
| 1.7.104.0 | 57198 | `0xAA6A60–0xAA6B09` | Registered reference EXE |

The plugin selects a map rebuild profile using all four parts of the detected Skyrim version and logs the selected Address Library ID. The native validator reads every profile directly from the same source table. All three x64 unwind entries cover 169 bytes, and a direct comparison found the complete function bodies byte-identical. The validator checks the full disassembly and confirms that no base relocation touches those bytes. It also checks the unwind range and base relocations in the packed originals of 1.5.97.0 and 1.6.1170.0. For those two versions the function bytes come from the qualified unpacked copies. Each profile therefore currently uses FNV-1a `0xFCCF8DDBA5FB3167` for code with SHA-256 `c5f82d50044b884915aac20c90349ed7019a761cae508f80ac7f30dcf7cffdf8`. If a graph needs a replacement map and the runtime has no verified profile or the live routine fails its guard, the plugin leaves the native table and IDs as they are. Reuse of an already matching table does not call the insert function.

For GOG 1.6.1179.0, the available SKSE 2.2.6 DLL and format-2 Address Library are valid reference inputs. A matching game EXE is required to qualify the GOG Havok writer. The fallback leaves the native map and IDs intact when a rewrite requires an unqualified ABI. VR is outside this Flat-Rim build configuration.

MO2 supplies loose files through its process-local virtual filesystem. Its loose HKX can be warmed through the current filesystem view. NTFS source and directory identity caches stay disabled there. OAR condition evaluation remains in OAR. This source review did not run Skyrim with MO2 or OAR.

### Automated coverage

The added cases cover malformed dense IDs, invalid map dimensions, unexpected staged buffer replacement, unqualified insert bodies, an incomplete topology write, the maximum legal state-machine map, concurrent invalidation of a shared transition, distinct offline variants, the offline admission limit, a combined cache write without a companion plan, a bounded HKX index update, OAR directory precedence and long-stall histogram buckets. All 467 checks passed in the x64 Release build.

Automated regressions exercise null edges, cycles, pointer identity, cloned actor fixtures, external fixture state, changed transitions, plan hash collisions, state-machine type changes, settings, packed widths, large graphs, exact table reuse, lifecycle invalidation, and damaged or interrupted disk cache reads and writes. This validates observable modeled behavior and data equality. Repeated in-game loads and animation behavior require a Skyrim test.

The Skyrim 1.7.104.0 reference provides native instruction and layout evidence. Hook boundaries and ABI for 1.5.97.0 and 1.6.1170.0 were verified on local unpacked analysis copies against their Address Libraries. The per-runtime report uses those copies when present and qualified. This is static compatibility evidence.
